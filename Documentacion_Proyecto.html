Integrantes: Aymane Benkara El Ghani, Diego Zamora, Unai Lopez

Curso: 2025-2026

Módulos: Desarrollo Web en Entorno Servidor / Cliente, Diseño de Interfaces

1. Introducción

a. Objetivo del proyecto

El objetivo principal de este proyecto es desarrollar una aplicación web funcional destinada a personas aficionadas a la lectura que disponen de libros en propiedad y desean compartirlos o prestarlos a otros usuarios sin ningún tipo de motivación económica. La plataforma sirve como un punto de encuentro y gestión para el intercambio cultural, digitalizando el proceso de préstamo tradicional.

b. Despliegue de la aplicación

La aplicación está diseñada para ser desplegada en un entorno estándar tipo LAMP/WAMP/XAMPP. Para su despliegue en un entorno local o de producción:

  1. Copiar el directorio Biblioteca en el directorio público del servidor web (ej. htdocs en XAMPP).
  2. Crear una base de datos MySQL/MariaDB llamada biblioteca.
  3. Importar el script SQL suministrado (sql/biblioteca.sql) para generar las tablas y datos semilla.
  4. Configurar las credenciales de base de datos en el archivo php/config/database.php si difieren del estándar (root sin contraseña).
  5. Acceder a la aplicación a través del navegador web local (ej. http://localhost/Biblioteca/).

2. Requisitos del proyecto

a. Requisitos implementados

Se han implementado satisfactoriamente la totalidad de los requisitos básicos exigidos:

  • Gestión de entidades: Gestión completa de libros, usuarios y préstamos.
  • Información de libros: Se almacena título, autor, género, año y adicionalmente, una URL de imagen de portada.
  • Información de usuarios: Registro con nombre, apellidos, email y contraseña encriptada (bcrypt).
  • Validación y Autenticación: Acceso restringido mediante validación por email y contraseña. Sólo usuarios registrados pueden operar.
  • Alta de libros: Formulario de alta para que los usuarios registren sus propios libros.
  • Préstamos: Sistema para pedir prestados libros disponibles, registrando fecha de inicio y marcando el libro como no disponible. No existe fecha límite de devolución.

Requisitos Extras / Valor Añadido implementados:

  • Inicio de sesión con Google (SSO): Integración con Google Identity Services para acceso rápido.
  • Panel de Administración: Un usuario administrador con privilegios para forzar devoluciones en caso de conflicto.
  • Sistema SPA: Navegación dinámica sin recargas completas de página utilizando JavaScript y peticiones asíncronas (Fetch API).

b. Requisitos no implementados

No existen requisitos básicos especificados en el documento que hayan quedado sin implementar. El proyecto cumple al 100% con la descripción original.

c. Propuestas de mejora

Para futuras versiones de la plataforma se proponen las siguientes mejoras:

  1. Sistema de Valoración (Reviews): Permitir a los usuarios puntuar y dejar reseñas de los libros leídos.
  2. Notificaciones Automáticas: Envío de correos electrónicos transaccionales cuando alguien solicita un libro o cuando un libro es devuelto.
  3. Buscador y Filtros Avanzados: Filtrado asíncrono por géneros, autores y años en el catálogo principal.

3. Diseño de la aplicación

a. Arquitectura general del proyecto

El proyecto sigue una arquitectura Cliente-Servidor (Frontend-Backend) bien diferenciada:

  • Frontend (Cliente): Responsable de la presentación y la interacción del usuario. Construido como una SPA, gestiona el estado en el cliente (usando localStorage) y se comunica con el servidor mediante peticiones HTTP asíncronas.
  • Backend (Servidor): Desarrollado en PHP bajo un patrón de Endpoints (API REST). Expone rutas que consumen y producen datos en formato JSON.
  • Capa de Datos: Base de datos relacional MySQL manejada mediante la extensión PDO garantizando seguridad contra Inyecciones SQL.

b. Diseño de la base de datos

El modelo relacional está compuesto por 3 tablas principales:

  1. usuarios: id (PK), nombre, apellidos, email (UNIQUE), password, es_admin, fecha_registro.
  2. libros: id (PK), titulo, autor, genero, anio, imagen_url, propietario_id (FK), fecha_alta.
  3. prestamos: id (PK), libro_id (FK), prestatario_id (FK), fecha_prestamo, fecha_devolucion.

c. Diseño de la interfaz de usuario

La interfaz sigue un diseño moderno, limpio y responsivo, priorizando la usabilidad:

  • Tipografía y Colores: Uso de fuentes legibles (Inter) y una paleta neutra para destacar el contenido.
  • Componentes: Interfaz basada en tarjetas (Cards) para mostrar la información visualmente.
  • Feedback: Integración de un sistema de notificaciones emergentes (Toasts) que informan de estado sin interrumpir.

4. Implementación

a. Tecnologías usadas. Librerías.

  • Frontend: HTML5, CSS3 Vanilla (Flexbox/Grid), Vanilla JavaScript (ES6+).
  • Librerías externas: Google Identity Services (Botón de Sign-In), Google Fonts. No se han utilizado frameworks pesados para mantener el proyecto ágil.
  • Backend: PHP 8.x.
  • Base de Datos: MySQL / MariaDB (extensión PDO nativa de PHP).

b. Endpoints creados: uso

La comunicación Frontend-Backend utiliza JSON en las siguientes rutas (API RESTful):

  • POST /php/auth/login.php: Inicia sesión de PHP.
  • POST /php/auth/registro.php: Registra un nuevo usuario.
  • POST /php/auth/google.php: Valida Token de Google (SSO).
  • GET /php/api/libros.php: Obtiene catálogo de libros.
  • POST /php/api/libros.php: Crea nuevo libro.
  • DELETE /php/api/libros.php: Elimina un libro.
  • GET /php/api/prestamos.php: Historial y estado de préstamos.
  • POST /php/api/prestamos.php: Solicitud de préstamo.
  • PUT /php/api/prestamos.php: Ejecuta la devolución (modificación).
